# Итоговая оценка готовности VibeEngine2

**Снимок оценки:** 2026-10-29  
**Ветка:** `master`  
**Назначение:** зафиксировать готовность первой версии отдельно для Editor, Game.Sandbox и Engine. Статус относится к текущей целевой конфигурации Windows x64 / .NET 8 и не является заявлением о поддержке всех платформ или сценариев.

## Итоговые статусы

| Область | Статус первой версии | Обоснование и границы |
|---|---|---|
| **Editor** | **Готово с известными ограничениями** | Разработчик подтверждает, что локальный набор тестов проходит. Основной workflow включает создание/открытие игрового проекта, Asset Browser, поддерживаемые редакторы документов, Play/Stop/Restart и диагностику. Удалённый CI в последних прогонах падал на таймаутах тестов, связанных с дочерними процессами, очисткой временных каталогов и асинхронной синхронизацией. Эти результаты не воспроизведены локально и не доказывают сами по себе дефект Editor. |
| **Game.Sandbox** | **Готово с известными ограничениями — интеграционный полигон** | Sandbox предназначен для проверки интеграции подсистем, а не как production-игра или обязательный шаблон пользовательского проекта. |
| **Engine** | **Готово с известными ограничениями** | В решении присутствуют и тестируются Runtime, ECS, Content, сериализация, графика, ввод, аудио, физика, навигация, частицы и другие механизмы. Готовность относится к подтверждённым сценариям и текущему desktop backend; она не означает, что каждая подсистема полностью универсальна или поддерживает все возможные данные и платформы. |

## Проверки и CI

Локальный набор тестов разработчик подтвердил как зелёный. Я не выполнял локальный запуск из этого аудита. Последние просмотренные GitHub Actions прогоны завершались ошибкой на отдельных тестах, поэтому зелёный удалённый прогон на актуальном состоянии не подтверждён.

Последний просмотренный run: [40871406223](https://github.com/Kostosik/VibeEngine2/actions/runs/40871406223). В нём 1195 из 1198 тестов прошли, а три завершились таймаутами:

- `ContentManagerTests.LoadAsync_AllRequestsCancelled_DisposesUnreferencedResult` — ожидание отмены/освобождения асинхронно загруженного ресурса;
- `EngineRuntimeBuilderTests.BuildAsync_WhenCancelledDuringPublish_PreservesExistingRuntime` — ожидаемая отмена публикации не была получена до таймаута;
- `GameProjectRunnerBuildTests.Stop_WhenExitedProcessHasDescendantHoldingOutput_DoesNotWaitIndefinitely` — ожидание игрового процесса завершилось по таймауту.

В предыдущих прогонах также встречались `UnauthorizedAccessException` при удалении временных каталогов с `Probe.dll` и `HotReloadProbe.exe`. В более позднем прогоне тест Hot Reload прошёл, но проблемы таймингов других тестов остались. Причина различия между локальным и GitHub Actions окружением не установлена.

**Решение для первой версии:** не менять Engine/Editor вслепую только по удалённым таймаутам, поскольку локально тесты проходят по сообщению разработчика. CI можно держать отключённым по решению разработчика; при этом отсутствие удалённого зелёного прогона остаётся известным ограничением процесса проверки, а не доказательством дефекта движка.

## Что подтверждено для Engine

Существующие тесты и ранее зафиксированные результаты покрывают, в частности:

- жизненный цикл Runtime, shutdown, владение ресурсами и обработку ошибок;
- ECS, пользовательские компоненты/системы и взаимодействие со сценами;
- загрузку ресурсов, кэширование, отмену async-запросов и reload;
- сериализацию, версионирование контейнеров и миграцию сохранений;
- камеру, Transform hierarchy, физические запросы и рендеринг спрайтов/тайлмапов;
- аудио, ввод и отдельные workflow частиц и скриптов;
- создание игрового проекта, публикацию вне репозитория Engine, запуск, остановку и повторный запуск.

Наличие отдельных тестов подтверждает только покрытые сценарии, а не все возможные данные, нагрузки и конфигурации.

## Ограничения первой версии

- **Платформа:** основная целевая конфигурация — Windows x64 и .NET 8. Поддержка других платформ этим отчётом не подтверждается.
- **Desktop backend:** стандартный `DesktopGameHost` использует OpenGL, Silk.NET для ввода и OpenAL для аудио. Универсальный выбор альтернативного backend не заявлен.
- **Аудио:** встроенный WAV loader поддерживает PCM, mono/stereo, 8/16 бит.
- **Изображения:** загрузчик принимает PNG, JPG/JPEG, BMP и TGA; имеющиеся тестовые свидетельства для формата следует трактовать в пределах конкретно проверенных случаев.
- **Content:** дополнительные loaders, например Script Definition JSON, необходимо регистрировать явно. Reload имеет ограничения при дополнительных внешних ссылках, зависимостях и активной загрузке.
- **Scripting/Networking и прочие расширяемые области:** использовать документированные API и проверенные сценарии; не считать наличие проекта доказательством завершённости всех потенциальных workflow.
- **Game.Sandbox:** интеграционный полигон, не production-игра.

## Итог

**Первая версия готова к использованию в заявленных границах, с известными ограничениями.** Это не означает, что каждый модуль завершён для всех типов игр. Рабочий сценарий создания проекта, разработки на C#, запуска и диагностики игры подтверждён документацией и тестами. Локальные тесты, по сообщению разработчика, проходят; стабильный зелёный GitHub Actions на актуальном состоянии не подтверждён, и причина расхождения остаётся открытой.

Для дальнейшего развития следует заводить конкретную задачу только при обнаружении реального блокирующего сценария или потребности проекта. Не требуется продолжать микрооптимизацию или добавлять новые архитектурные подсистемы исключительно ради формального расширения движка.
