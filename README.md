# VibeEngine2

**VibeEngine2** — модульный игровой движок на C# и .NET 8 с ECS/runtime-инфраструктурой, 2D-графикой и редактором игровых проектов.

Главный принцип архитектуры: **движок предоставляет механизмы, игра определяет их смысл**. Компоненты, системы и правила конкретной игры располагаются в игровом проекте, а не в Engine.

Первая целевая конфигурация — **desktop на Windows x64**. Наличие подсистемы в репозитории не означает, что у неё нет ограничений или что она проверена на всех платформах и для всех сценариев. Подтверждённые возможности и ограничения описаны в [матрице поддержки](docs/SUPPORT_MATRIX.md).

## Возможности

- ECS, runtime и управление жизненным циклом игры.
- Создание игровых проектов в редакторе, запуск, остановка и повторный запуск игры.
- Обычный C#-проект игры, который можно открыть во внешней IDE.
- Работа с игровыми ресурсами через Asset Browser и относительные пути проекта.
- Сцены и сериализация поддерживаемых компонентов.
- 2D-графика, камера, спрайты, тайловые карты и эффекты частиц.
- Ввод, UI, физика, аудио, Content pipeline, диагностика и другие специализированные подсистемы.
- Подключение собственных ECS-компонентов и систем из сборки игры.

Список выше описывает основные области движка, а не обещание полной функциональности каждой подсистемы. Уточняйте ограничения в [матрице поддержки](docs/SUPPORT_MATRIX.md).

## Требования

Для разработки из исходников:

- Windows x64.
- .NET 8 SDK.
- Git.

Поставка редактора собирается как framework-dependent Windows-приложение. Для запуска готовой поставки требуется подходящая среда выполнения .NET 8 для Windows Desktop. Поддержка других ОС и платформ в первой целевой конфигурации не заявляется.

## Запуск из исходников

Из корня репозитория выполните:

```powershell
dotnet restore .\VibeEngine2.sln
dotnet run --project .\Editor.Sandbox\Editor.Sandbox.csproj
```

`Editor.Sandbox` — приложение редактора и интеграционный полигон для проверки взаимодействия подсистем. Это не обязательная основа пользовательской игры и не шаблон её архитектуры.

Чтобы собрать и проверить всё решение:

```powershell
dotnet build .\VibeEngine2.sln --configuration Release
dotnet test .\VibeEngine2.sln --configuration Release
```

Успешный локальный запуск этих команд подтверждает только ту конфигурацию и те тесты, которые были выполнены. Он не доказывает поддержку всех платформ, backend и вариантов данных.

## Основной рабочий сценарий

1. Запустите редактор и создайте игровой проект в выбранном каталоге.
2. Откройте созданный проект и при необходимости используйте **Open IDE**, чтобы открыть его решение или файл проекта во внешней IDE.
3. Разрабатывайте игровую логику в обычном C#/.NET-проекте. Используйте Asset Browser для ресурсов проекта и поддерживаемые инструменты редактора для сцен и других документов.
4. Запускайте игру командами **Play**, **Stop** и **Restart**. Вывод сборки и игрового процесса доступен в консоли редактора.
5. Проверяйте сборку и публикацию проекта отдельно от исходников VibeEngine2, если именно такой вариант предполагается для распространения игры.

Созданный проект использует подготовленные библиотеки движка в каталоге `Engine/` и локальные ссылки на них. Это текущая модель поставки первой версии; NuGet-пакеты и универсальный менеджер пакетов не являются обязательной частью этого workflow.

## Границы первой версии

- Основная подтверждённая desktop-конфигурация — Windows x64 и .NET 8.
- Стандартный desktop host использует OpenGL, Silk.NET для ввода и OpenAL для аудио; универсальный переключатель между альтернативными backend не заявлен.
- Форматы ресурсов и ограничения загрузчиков определены в матрице поддержки и соответствующих разделах API-документации.
- `Game.Sandbox` служит интеграционным полигоном, а не production-игрой.
- Не следует считать сетевые, scripting, 3D или другие имеющиеся в репозитории направления полностью готовыми только на основании присутствия соответствующих проектов. Ориентируйтесь на документированные и проверенные сценарии.
