# Итоговая оценка готовности VibeEngine2

**Снимок оценки:** 2026-10-29  
**Ветка:** `master`  
**Назначение:** зафиксировать статус Editor, Game.Sandbox и Engine отдельно. Этот документ не объявляет проект готовым к production, если проверочный CI остаётся красным или результат ещё не получен.

## Итоговые статусы

| Область | Статус | Обоснование |
|---|---|---|
| **Editor** | **Не готово к закрытию production readiness** | Основные рабочие сценарии помечены в ROADMAP как пройденные; существуют проверки создания проекта, workspace, стартовой сцены, сборки/перезапуска, завершения процессов и диагностики ошибок. Однако один из последних завершённых CI запусков упал в тесте остановки процесса из-за `UnauthorizedAccessException` при удалении временной папки с `Probe.dll`. После этого не получено подтверждение полностью зелёного тестового прогона для актуального состояния `master`. |
| **Game.Sandbox** | **Готово с известными ограничениями — как интеграционный полигон** | ROADMAP отмечает Sandbox Readiness выполненным, а Release-сборка решения проходила в недавних CI прогонах, которые завершились ошибкой уже на шаге тестов. Sandbox предназначен для проверки взаимодействия подсистем, а не как шаблон пользовательской игры или готовая самостоятельная production-игра. Подтверждённый workflow дистрибутива ориентирован на Windows x64 и .NET 8; свежий успешный запуск отдельного workflow сборки ZIP в этой проверке не найден. |
| **Engine** | **Не готово к закрытию production readiness** | Покрыты тестами многие механизмы Runtime, ECS, Content, сериализации, физики и графики. При этом `ContentManagerTests.LoadAsync_AllRequestsCancelled_DisposesUnreferencedResult` завершился с `TimeoutException` в двух последних просмотренных завершённых CI прогонах. До выяснения причины и получения стабильного зелёного тестового прогона нельзя подтвердить весь Engine как прошедший production readiness. |

## CI и конкретные свидетельства

CI-конфигурация в `.github/workflows/dotnet.yml` выполняет restore, Release build и весь набор тестов решения на `windows-latest` с .NET 8.

Это повторяющийся сигнал, требующий проверки реализации и теста, а не предположение о случайной нестабильности. |

Поэтому этот run нельзя считать успешным. |

### Что именно подтверждено для Engine

Существующие тесты проверяют, в частности:

- lifecycle, shutdown, владение ресурсами и диагностику `EngineRuntime`;
- загрузку ресурсов, кэш, отмену async-запросов и hot reload в Content;
- сериализацию, ограничение размера payload, проверку версии контейнера и миграцию сохранений;
- форматы WAV и ошибки некорректных аудиоданных;
- геометрию камеры, физические запросы, иерархию Transform и рендеринг спрайтов/тайлмапов.

Это свидетельствует о широкой автоматизированной проверке, но не заменяет зелёный запуск всего набора тестов. Индивидуальные тесты подтверждают конкретные сценарии, а не все возможные нагрузки, backend или данные.

## Ограничения, входящие в текущую оценку

- **Платформа:** актуальные CI и workflow дистрибутива настроены для Windows x64 и .NET 8. Поддержка других платформ здесь не подтверждена.
- **Desktop backend:** стандартный `DesktopGameHost` непосредственно создаёт окно OpenGL, ввод Silk.NET и аудио OpenAL; настройки выбора альтернативного backend нет.
- **Аудиоформат:** встроенный загрузчик принимает WAV с PCM, mono/stereo и 8/16 бит.
- **Изображения:** загрузчик принимает расширения PNG, JPG/JPEG, BMP и TGA; в найденном тесте явно проверено только PNG → RGBA8.
- **Загрузка Content:** дополнительные loaders, например JSON Script Definition, необходимо регистрировать явно. Операция reload имеет ограничения при дополнительных внешних ссылках, зависимостях и активной загрузке.
- **Sandbox:** это интеграционный полигон. Его конкретные ссылки на подсистемы и backend не являются обязательной архитектурой пользовательской игры.

Подробности форматов и ограничений: [`SUPPORT_MATRIX.md`](SUPPORT_MATRIX.md). Расположение реализации по проектам: [`PROJECT_INDEX.md`](PROJECT_INDEX.md). Типовые проблемы проекта и сборки: [`TROUBLESHOOTING.md`](TROUBLESHOOTING.md).

## Что нужно сделать, чтобы снять блокирующие пункты

1. Локально воспроизвести и устранить причину тайм-аута `LoadAsync_AllRequestsCancelled_DisposesUnreferencedResult`; затем прогнать тест Content отдельно и весь Release test suite. Не считать тест исправленным только потому, что он один раз прошёл.
2. Разобраться с ошибкой очистки `Probe.dll` в тесте завершения процесса Editor Runner; подтвердить, что дерево процессов завершается и временные файлы освобождаются, а полный тестовый прогон стабилен.
3. Получить завершённый успешный GitHub Actions run на актуальном коде. Проверять не только Release build, но и шаг тестов.
4. Если требуется подтвердить готовность распространяемой сборки, отдельно запустить manual workflow `.github/workflows/build-distribution.yml` и проверить, что ZIP создан и успешно прошёл предусмотренную проверку состава.

## Решение по production readiness

На момент этого снимка **не следует объявлять VibeEngine2 целиком готовым к production**. Game.Sandbox можно считать готовым к своей узкой роли интеграционного полигона с указанными ограничениями. Для Engine и Editor production readiness остаётся незакрытым до выяснения причин красных тестов и успешного полного CI.

Этот документ фиксирует текущее решение, а не утверждает, что неисправность уже исправлена. После стабильного зелёного прогона и повторной проверки статусы следует обновить.
